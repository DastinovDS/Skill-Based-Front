# Первый живой матч: ручной чек-лист (QA-01, #68)

Чек-лист живого матча на настоящем стеке (Caddy со собранным клиентом + сервер в Docker), без моков.
Автоматизируемая часть повторяется Playwright E2E (`e2e/`, QA-02 #84, раздел «E2E» в `README.md`),
остальное делает человек. Отметка `[x]` значит «проверено», рядом написано чем и когда.

Прогон 2026-10-07: стек из `compose.yaml` + `e2e/compose.e2e.yaml` (рулсет `test-short`, окно
переподключения и пауза по 10 с), порт 8080; команды (раздел 4) дополнительно на `mvp-0` (15 минут, DEC-22); два
игрока: два контекста Playwright и, для интерфейса, две вкладки встроенного браузера на разных
origin (`localhost` и `bob.localhost`: у разных origin отдельный `localStorage`, то есть отдельный
гость). Итог: найдено и заведено 4 бага (раздел 9), один из них (#183, белый экран прод-сборки)
исправлен в том же PR; остаток: прогон на двух разных компьютерах (раздел 8) и осада.

## 0. Подготовка стенда

```sh
# Порты 80/443 заняты чужим стеком: 8080/8443. SITE_ADDRESS=:80 пускает любой Host (нужно для
# второго «компьютера» по другому имени или адресу); по умолчанию Caddy отвечает только на localhost.
export HTTP_PORT=8080 HTTPS_PORT=8443 SITE_ADDRESS=:80
docker compose -f compose.yaml -f e2e/compose.e2e.yaml up --build -d --wait
curl -s localhost:8080/api/health          # {"status":"ok"}
```

- `e2e/compose.e2e.yaml`: `GOW_ENV=e2e`, рулсет `test-short` (партия 60 секунд), окно переподключения
  и пауза по 10 секунд. Для прогона боевого рулсета (раздел 4) добавьте третий файл с
  `GOW_RULESET_PATH: /app/rulesets/mvp-1.toml` в `services.app.environment`.
- Второй игрок: другой браузер, приватное окно или другой origin (`http://bob.localhost:8080`). Две вкладки
  одного origin делят гостя в `localStorage` (`sbf.guest`), это один и тот же игрок.
- Остановить: `docker compose -f compose.yaml -f e2e/compose.e2e.yaml down` (данные остаются в томах).

## 8. Два разных компьютера через интернет **[вручную]**

1. Поднять стек на своей машине как в разделе 0 (`SITE_ADDRESS=:80`).
