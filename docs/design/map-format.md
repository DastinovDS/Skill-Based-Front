# Формат карты

Карта MVP: JSON-файл в `maps/`. Загрузчик: `gow_sim.maps.load_map(path) -> MapDef` (MAP-01, #13).
Проверки дизайна карты (связность, планарность, симметрия атрибутов, нейтральное пространство)
выполняет офлайн-валидатор `uv run gow-maps validate maps/*.json` (MAP-02, #14).

Правила игры, которые опираются на поля карты, описаны в [`mechanics.md`](mechanics.md): рельеф
(раздел 4), дороги (раздел 8), города и ёмкость (раздел 9), VP (раздел 11).

## Общие правила

- **Все числа целые.** `1.0`, `"1"` и `true` вместо числа: ошибка загрузки.
- **Id узлов и рёбер равны их позиции в списке:** `nodes[i].id == i`, `edges[i].id == i`.
  Внутри симуляции узлы и рёбра хранятся по этим id.
- **Неизвестный или отсутствующий ключ:** ошибка (опечатка не проходит молча).
- Игроки MVP: `0` и `1`. «Нет владельца»: `null`.
- Координаты: целые «единицы мира» в прямоугольнике `[0, width] × [0, height]`, ось `y` вниз
  (как на экране).

Ошибка загрузки называет файл и поле: `maps/x.json: nodes[3].vp: expected an integer, got 1.5`.

## Структура

```json
{
  "meta":   {"name": "line3", "version": 1, "symmetry": "rot180", "width": 400, "height": 200},
  "nodes":  [{"id": 0, "x": 100, "y": 100, "terrain": "mountains", "vp": 1, "base_capacity": 4,
              "capital_of": 0, "start_owner": 0, "start_units": 3, "start_charged": 3, "start_stock": 4}],
  "edges":  [{"id": 0, "a": 0, "b": 1, "base_width": 1, "max_width": 3, "travel_ticks": 30}],
  "mirror": {"nodes": {"0": 2, "1": 1, "2": 0}, "edges": {"0": 1, "1": 0}}
}
```

### `meta`

| Поле | Тип | Значение |
|---|---|---|
| `name` | строка `[A-Za-z0-9_-]+` | id карты (`map_id` в реплее и протоколе) |
| `version` | целое ≥ 1 | ревизия карты; повышается при любой правке |
| `symmetry` | `"rot180"` | тип симметрии; в MVP только поворот на 180° |
| `width`, `height` | целые ≥ 1 | размер мира; центр поворота: `(width / 2, height / 2)` |

### `nodes[]`

В MVP **каждый узел — город со складом** (mechanics.md, раздел 9).

| Поле | Тип | Значение |
|---|---|---|
| `id` | целое | равно индексу в списке |
| `x`, `y` | целые | позиция, `0 ≤ x ≤ width`, `0 ≤ y ≤ height` |
| `terrain` | `plains` \| `forest` \| `mountains` | рельеф: равнина, лес, горы (mechanics.md, раздел 4) |
| `vp` | целое ≥ 0 | VP за удержание города; у столицы множитель из рулсета (DEC-03) |
| `base_capacity` | целое ≥ 0 | база ёмкости до вклада дорог (mechanics.md, раздел 9) |
| `capital_of` | `null` \| `0` \| `1` | чья это столица |
| `start_owner` | `null` \| `0` \| `1` | владелец на старте |
| `start_units` | целое ≥ 0 | стартовый гарнизон: число юнитов |
| `start_charged` | целое, `0..start_units` | из них заряжены |
| `start_stock` | целое ≥ 0 | стартовый запас склада в зарядах |

Загрузчик дополнительно требует:

- у каждого игрока ровно одна столица, и на старте она принадлежит ему;
- **нейтральный узел** (`start_owner: null`) пуст: `start_units`, `start_charged` и `start_stock`
  равны 0. Нейтральных гарнизонов в MVP нет.

### `edges[]`

Дорога неориентирована. Между двумя узлами не больше одной дороги, петли запрещены.

| Поле | Тип | Значение |
|---|---|---|
| `id` | целое | равно индексу в списке |
| `a`, `b` | id узлов | концы дороги, `a ≠ b` |
| `base_width` | целое, `1..max_width` | ширина на старте |
| `max_width` | целое, `1..5` | предел улучшения (SIM-11); 5: последняя ширина таблицы ёмкости (mechanics.md, раздел 9) |
| `travel_ticks` | целое ≥ 1 | базовое время прохода в тиках; модификатор рельефа узла входа берётся из рулсета (`terrain.entry_speed_pct`) |

`travel_ticks` согласован с геометрической длиной дороги; допуск проверяет валидатор (MAP-02).

### `mirror`

Таблица симметрии: `nodes` и `edges` отображают id в id зеркального объекта при повороте на 180°.
Ключи: id в виде строк (так устроен JSON), значения: целые id.

- Таблица полная (у каждого узла и ребра есть зеркало) и является инволюцией: `m(m(x)) == x`.
- Узел в точном центре карты зеркален сам себе; его `start_owner` и `capital_of` равны `null`.
- Зеркало ребра `(a, b)` соединяет `m(a)` и `m(b)`.
- У зеркального узла те же атрибуты, а `capital_of` и `start_owner` переходят к другому игроку;
  координаты: `(width − x, height − y)`.

Загрузчик проверяет только полноту и инволютивность. Совпадение атрибутов, концов рёбер и координат
проверяет валидатор (MAP-02).

**Зачем таблица симуляции.** Тай-брейки по узлам идут через `MapDef.node_key(player, node)`:
для игрока 0 это id узла, для игрока 1 — id зеркального узла (`AGENTS.md`, раздел 4.1, правило 6).
Поэтому решение в зеркальной позиции тоже зеркально, и тест зеркальности (SIM-05) не ловит
преимущества стороны, внесённого порядком id.

## `MapDef` в коде

`gow_sim.maps` (только стандартная библиотека):

- `MapDef(meta, nodes, edges, mirror_nodes, mirror_edges, incident)`: frozen dataclass; `nodes` и
  `edges` — кортежи `NodeDef` и `EdgeDef`, индекс равен id; `incident[n]` — id рёбер узла `n`
  по возрастанию.
- `MapDef.capital(player)`, `MapDef.node_key(player, node)`, `EdgeDef.other(node)`.
- `load_map(path)` и `parse_map(data)`; ошибки: `MapFormatError` (подкласс `ValueError`).

| Файл | Что это |
|---|---|

| `pass.json` | «перевал»: у каждого игрока столица и передовой город, между ними единственный проход через горный узел хребта |
