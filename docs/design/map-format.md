# Формат карты

Карта MVP: JSON-файл в `maps/`. Загрузчик: `gow_sim.maps.load_map(path) -> MapDef` (MAP-01, #13).
Проверки дизайна карты (связность, планарность, симметрия правил, названия, точки границы,
нейтральное пространство) выполняет офлайн-валидатор `uv run gow-maps validate maps/*.json` (MAP-02, #14).

Правила игры, которые опираются на поля карты, описаны в [`mechanics.md`](mechanics.md): рельеф
(раздел 4), дороги (раздел 8), города и ёмкость (раздел 9), VP (раздел 11).

## Изменения формата по DEC-23 (реализованы)

> Решение [принято]: DEC-23 (#235), mechanics.md, раздел 9; связанные правила: DEC-21 (#233, точка
> границы), DEC-22 (#234, ёмкость по виду узла, уровни дорог). DEC-22 (#238) ввёл `kind` вместо
> `base_capacity`; остальное (`name`, `border_permille`, `max_level` вместо `max_width`, удаление
> `base_width`, проверки валидатора, половина карты) реализовано в #366 (`SIM_VERSION` 20,
> `PROTOCOL_VERSION` 24). Карты с провинциями: #266. Таблица ниже: история изменения, текущий
> формат описан в разделах «Структура» и дальше.

| Где | Было | Станет |
|---|---|---|
| `nodes[]` | `base_capacity` | удаляется; новое `kind`: `capital` \| `city_large` \| `city_medium` \| `city_small` \| `province`, ёмкость по виду из рулсета (`capacity.by_kind`) |
| `nodes[]` | (нет) | `name`: название узла, строка 1..24 символа без пробелов по краям, уникальная в карте, не переводится |
| `nodes[]` провинции | (нет) | `vp = 0`, `capital_of = null`, `start_units = start_charged = start_stock = 0`; `start_owner` любой |
| `nodes[]` | (нет) | `kind = capital` тогда и только тогда, когда `capital_of` не `null` |
| `edges[]` | `base_width`, `max_width` (1..5) | `base_width` удаляется (все дороги начинают с уровня 1 без типа); `max_level`, 1..3 |
| `edges[]` | (нет) | `border_permille`: точка границы в тысячных от конца `a`, 100..900, обязательна в готовой карте |
| `mirror` | атрибуты равны | `kind` равен, `name` свой; `border_permille` зеркального ребра равен исходному, если его конец `a` = `m(a)`, иначе `1000 - border_permille`; ребро, зеркальное само себе: 500 |
| половина карты | (нет) | у узла `name` и `mirror_name` (у центрального только `name`); `border_permille` у ребра необязателен (500); копия `cross_edge` получает `1000 - border_permille`, `cross_edge` с `a == b` требует 500 |
| валидатор | (нет) | проверки `names`, `border` (диапазон и симметрия), `kinds` (провинции, столицы); `symmetry` сравнивает `kind` и `border_permille` с учётом направления. **Реализовано:** диапазон `border_permille` и `kinds` (пп. 2, 3) проверяет загрузчик (ошибка `format`, примеры 1-3 и 5 DEC-23), симметрию точки границы проверка `border`, `kind` проверка `symmetry` |

## Общие правила

- **Все числа целые.** `1.0`, `"1"` и `true` вместо числа: ошибка загрузки.
- **Id узлов и рёбер равны их позиции в списке:** `nodes[i].id == i`, `edges[i].id == i`.
  Внутри симуляции узлы и рёбра хранятся по этим id.
- **Неизвестный или отсутствующий ключ:** ошибка (опечатка не проходит молча).
- Игроки MVP: `0` и `1`. «Нет владельца»: `null`.
- Координаты: целые «единицы мира» в прямоугольнике `[0, width] × [0, height]`, ось `y` вниз
  (как на экране).

Ошибка загрузки называет файл и поле: `maps/x.json: nodes[3].vp: expected an integer, got 1.5`.

## Структура

```json
{
  "meta":   {"name": "line3", "version": 1, "symmetry": "rot180", "width": 400, "height": 200},
  "nodes":  [{"id": 0, "name": "Каменец", "x": 100, "y": 100, "terrain": "mountains", "vp": 1,
              "kind": "capital", "capital_of": 0, "start_owner": 0, "start_units": 3,
              "start_charged": 3, "start_stock": 4}],
  "edges":  [{"id": 0, "a": 0, "b": 1, "max_level": 3, "travel_ticks": 30, "border_permille": 500}],
  "mirror": {"nodes": {"0": 2, "1": 1, "2": 0}, "edges": {"0": 1, "1": 0}}
}
```

### `meta`

| Поле | Тип | Значение |
|---|---|---|
| `name` | строка `[A-Za-z0-9_-]+` | id карты (`map_id` в реплее и протоколе) |
| `version` | целое ≥ 1 | ревизия карты; повышается при любой правке |
| `symmetry` | `"rot180"` | тип симметрии: игроки и узлы меняются местами по таблице `mirror` (DEC-27, п. 6); геометрического поворота картинки не требуется |
| `width`, `height` | целые ≥ 1 | размер мира |

### `nodes[]`

Узел: город со складом или провинция, узел без города (`kind = province`, DEC-23, п. 2;
mechanics.md, раздел 9).

| Поле | Тип | Значение |
|---|---|---|
| `id` | целое | равно индексу в списке |
| `name` | строка | название узла (DEC-23, п. 4): 1..24 символа без пробелов по краям, уникальное в карте, не переводится (длину, пробелы и уникальность проверяет валидатор, `names`) |
| `x`, `y` | целые | позиция, `0 ≤ x ≤ width`, `0 ≤ y ≤ height` |
| `terrain` | `plains` \| `forest` \| `mountains` | рельеф: равнина, лес, горы (mechanics.md, раздел 4) |
| `vp` | целое ≥ 0 | VP за удержание города; у столицы множитель из рулсета (DEC-03) |
| `kind` | `capital` \| `city_large` \| `city_medium` \| `city_small` \| `province` | вид узла; ёмкость по виду из рулсета `capacity.by_kind`, от дорог не зависит (DEC-22) |
| `capital_of` | `null` \| `0` \| `1` | чья это столица |
| `start_owner` | `null` \| `0` \| `1` | владелец на старте |
| `start_units` | целое ≥ 0 | стартовый гарнизон: число юнитов |
| `start_charged` | целое, `0..start_units` | из них заряжены |
| `start_stock` | целое ≥ 0 | стартовый запас склада в зарядах (DEC-26: при `city_upgrades.enabled` не больше стартовой ёмкости склада вида узла) |

Загрузчик дополнительно требует:

- у каждого игрока ровно одна столица, и на старте она принадлежит ему;
- `kind = capital` тогда и только тогда, когда `capital_of` не `null` (DEC-23, п. 3);
- у провинции `vp = 0` и нет гарнизона и склада (DEC-23, п. 2);
- **нейтральный узел** (`start_owner: null`) пуст: `start_units`, `start_charged` и `start_stock`
  равны 0. Нейтральных гарнизонов в MVP нет.

### `edges[]`

Дорога неориентирована. Между двумя узлами не больше одной дороги, петли запрещены.

| Поле | Тип | Значение |
|---|---|---|
| `id` | целое | равно индексу в списке |
| `a`, `b` | id узлов | концы дороги, `a ≠ b` |
| `max_level` | целое, `1..3` | последний уровень улучшения (DEC-22, DEC-23, п. 6); все дороги начинают с уровня 1 без типа, стартового уровня в карте нет |
| `travel_ticks` | целое ≥ 1 | базовое время прохода в тиках; скорость по зонам рельефа концов ребра из рулсета (`terrain.speed_pct`, mechanics.md, раздел 4) |
| `border_permille` | целое, `100..900` | точка границы в тысячных длины от конца `a`, 500: середина (DEC-23, п. 5): делит ребро на половины для обзора (DEC-21) и зоны рельефа для скорости (mechanics.md, раздел 4) |

`travel_ticks` согласован с нарисованной длиной дороги; допуск проверяет валидатор (раздел «Валидатор»).
Старые поля `base_width`, `max_width` и `base_capacity` загрузчик отклоняет как неизвестные ключи
(DEC-23, п. 9).

### Вид узлов в картах MVP (до DEC-23)

Три карты MVP получили `kind` из прежних данных по одному правилу (замена `base_capacity` и вклада
дорог, #238), пока их не переделает issue карт DEC-23 (#266). Названия узлов (DEC-23, п. 4) они
получили в #366, точки границы у них все 500:

- столица: `capital`;
- остальные узлы по числу дорог (степени): 1-2 дороги `city_small`, 3-4 `city_medium`, 5 и больше
  `city_large` (прежняя ёмкость снабжаемого города была примерно `3 + степень`);
- узел с `vp >= 2` поднимается на один класс (не выше `city_large`): ценный город держит больше.

Дороги: все начинают с уровня 1 (прежние стартовые ширины 2 и 3 сняты), `max_level` равен прежнему
`max_width`, но не больше 3.

### `mirror`

Таблица симметрии: `nodes` и `edges` отображают id в id зеркального объекта: игроки меняются
местами, правила для них одинаковы (симметрия правил, а не картинки: DEC-27, п. 1). Ключи: id в
виде строк (так устроен JSON), значения: целые id.

- Таблица полная (у каждого узла и ребра есть зеркало) и является инволюцией: `m(m(x)) == x`.
- Узел может быть зеркален сам себе; его `start_owner` и `capital_of` равны `null`.
- Зеркало ребра `(a, b)` соединяет `m(a)` и `m(b)`; его `border_permille` равен исходному, если
  его конец `a` равен `m(a)`, иначе `1000 − border_permille`; ребро, зеркальное само себе, имеет 500
  (DEC-23, п. 7).
- У зеркального узла те же атрибуты (`kind`, `terrain`, `vp`, стартовые поля), а `capital_of` и
  `start_owner` переходят к другому игроку; `name` свой. **Координаты свободны** (DEC-27, п. 1):
  требования `(width − x, height − y)` нет, картинка сторон может различаться.

Загрузчик проверяет только полноту и инволютивность. Совпадение атрибутов, концов рёбер и точек
границы проверяет валидатор (MAP-02).

**Зачем таблица симуляции.** Тай-брейки по узлам идут через `MapDef.node_key(player, node)`:
для игрока 0 это id узла, для игрока 1 — id зеркального узла (`AGENTS.md`, раздел 4.1, правило 6).
Поэтому решение в зеркальной позиции тоже зеркально, и тест зеркальности (SIM-05) не ловит
преимущества стороны, внесённого порядком id.

## Тип карты в клиенте

Клиент читает файл карты по типу `MapFile` из `apps/client/src/protocol.gen.ts`. Тип сгенерирован
из модели `gow_protocol.mapfile.MapFile` (PRO-02, #45): она описывает только форму и типы значений,
а ссылки, диапазоны между полями и зеркало проверяет загрузчик. Тест
`packages/protocol/tests/test_mapfile.py` проверяет, что модель и загрузчик согласны на всех картах
`maps/` и `packages/sim/tests/maps/`. Поменял формат: поправь загрузчик, модель и перегенерируй типы
(`AGENTS.md`, раздел 3).

## `MapDef` в коде

`gow_sim.maps` (только стандартная библиотека):

- `MapDef(meta, nodes, edges, mirror_nodes, mirror_edges, incident)`: frozen dataclass; `nodes` и
  `edges` — кортежи `NodeDef` и `EdgeDef`, индекс равен id; `incident[n]` — id рёбер узла `n`
  по возрастанию.
- `MapDef.capital(player)`, `MapDef.node_key(player, node)`, `EdgeDef.other(node)`.
- `load_map(path)` и `parse_map(data)`; ошибки: `MapFormatError` (подкласс `ValueError`).
- `map_to_data(map)`: обратное к `parse_map` (данные в формате файла); так карта входит в каноническое состояние и `state_hash()` (SIM-02).

## Валидатор

`uv run gow-maps validate <файлы>` (MAP-02, #14) загружает каждую карту и проверяет дизайн.
Вывод: `OK <файл>` или `FAIL <файл>` со списком `[проверка] сообщение`; код выхода 1, если
хоть одна карта не прошла. Шаблоны вроде `maps/*.json` раскрываются и самим CLI (bash передаёт
несовпавший шаблон как есть). Пороги: `tools/maps/src/gow_maps/validate.toml`, другой файл:
`--config <путь>`.

| Проверка | Что требует |
|---|---|
| `format` | карта загружается `gow_sim.maps` (типы, ссылки, диапазоны, в том числе `border_permille` 100..900 и `max_level` 1..3, пустые нейтральные узлы, провинции и столицы по DEC-23, пп. 2, 3) |
| `size` | `min_nodes..max_nodes` узлов (45..55, DEC-27, п. 5); **по умолчанию выключена** (`size_check = false`), включается своим файлом порогов `--config` |
| `names` | у каждого узла название 1..24 символа без пробелов по краям, названия не повторяются (DEC-23, п. 4) |
| `connectivity` | граф связен |
| `planarity` | дороги не пересекаются и не накладываются, дорога не проходит через чужой город, у городов разные координаты (проверяются фактические координаты: при свободных координатах это главная защита от пересечений, DEC-27, п. 5) |
| `symmetry` | таблица `mirror` меняет игроков местами: одинаковые атрибуты узлов (`kind`, `terrain`, `vp`, стартовые поля) и рёбер (`max_level`, `travel_ticks`), владелец и столица переходят к другому игроку, концы зеркального ребра зеркальны; координаты и названия не сравниваются (DEC-27, п. 1) |
| `border` | `border_permille` зеркального ребра с учётом направления: равен исходному, если конец `a` зеркала равен `m(a)`, иначе `1000 − border_permille`; у ребра, зеркального самому себе, 500 (DEC-23, п. 7) |
| `degree` | у узла не больше `max_degree` (5) дорог |
| `disjoint_paths` | от каждой столицы к каждому узлу с `vp ≥ 2` не меньше 2 путей без общих дорог |
| `neutral_space` | не меньше 20% узлов без стартового владельца, у которых расстояния до двух столиц (в дорогах) отличаются не больше чем на 1 |
| `travel_ticks` | нарисованная длина согласована со временем (DEC-27, п. 4): `|travel_ticks − e| × 100 ≤ 15 × e`, `e = длина × 30 / 100` (100 единиц мира = 3 секунды), допуск не меньше 1 тика; зеркальные рёбра с одним `travel_ticks` поэтому различаются по длине не больше допуска |

Проверки путей и расстояний выполняются только на связном графе. «Плохие» фикстуры для каждой
проверки: `tools/maps/tests/fixtures/`.

## Половина карты и отзеркаливание

Карты MVP рисуются наполовину, вторую половину строит скрипт (MAP-03, #15):

```bash
uv run gow-maps mirror maps/src/<name>.half.json -o maps/<name>.json
```

Скрипт строит зеркальную копию половины (по умолчанию поворотом на 180°, или в заданных
координатах), сшивает дороги через центральную полосу, назначает id, названия, точки границы и
таблицу `mirror`, пишет карту и сразу прогоняет её через валидатор (код выхода 1, если карта не
прошла; файл при этом остаётся для разбора).

Формат половины (`maps/src/<name>.half.json`):

```json
{
  "meta":  {"name": "diamond", "version": 1, "width": 400, "height": 400},
  "nodes": [{"id": "capital", "name": "Каменец", "mirror_name": "Кремнёв", "x": 100, "y": 200,
             "terrain": "mountains", "vp": 1, "kind": "capital", "capital_of": 0, "start_owner": 0,
             "start_units": 3, "start_charged": 3, "start_stock": 4},
            {"id": "north", "name": "Утёс", "mirror_name": "Кряж", "x": 200, "y": 100,
             "mirror_x": 190, "mirror_y": 310, "terrain": "forest", "vp": 2, "...": "..."},
            {"id": "ford", "name": "Брод", "self_mirror": true, "x": 210, "y": 190, "...": "..."}],
  "edges":       [{"a": "capital", "b": "north", "max_level": 3, "border_permille": 400}],
  "cross_edges": [{"a": "capital", "b": "north", "max_level": 3}]
}
```

- `meta` без `symmetry`: в готовой карте всегда `"rot180"` (замена игроков по таблице `mirror`).
- `nodes[].id`: строковая метка, уникальная в файле; остальные поля как у карты, плюс:
  - `mirror_name`: название копии (DEC-23, п. 8), обязательно у узла с копией;
  - `mirror_x`, `mirror_y` (необязательные, DEC-27, п. 6): координаты копии; без них копия в
    `(width − x, height − y)`, как в половинах до DEC-27;
  - `self_mirror: true` (необязательный): узел зеркален сам себе в любых координатах и не
    копируется; у него только `name`, без `mirror_name`, `mirror_x`, `mirror_y`. Без флага сам себе
    зеркален узел в точном центре `(width / 2, height / 2)` без `mirror_x`, `mirror_y` (половины до
    DEC-27; такой узел не больше одного).

  У копии `capital_of` и `start_owner` переходят к другому игроку, остальные атрибуты те же.
- `edges[]`: дорога между двумя узлами половины; копия соединяет их зеркала с тем же
  `border_permille`. Дорога между двумя узлами, зеркальными самим себе, зеркальна сама себе: она
  пишется один раз и требует `border_permille` 500.
- `cross_edges[]`: дорога через центральную полосу от узла `a` к **зеркалу** узла `b`; её копия
  идёт от `b` к зеркалу `a` и получает `1000 − border_permille`. При `a == b` получается одна
  дорога, зеркальная сама себе: `border_permille` только 500, иначе ошибка скрипта. Узел,
  зеркальный сам себе, соединяется обычными `edges`.
- `border_permille` у дорог необязателен (500); в готовую карту скрипт пишет его всегда.
- `travel_ticks` у дорог можно не указывать: скрипт посчитает его по средней нарисованной длине
  дороги и её копии (при повороте длины равны) с тем же масштабом, что у валидатора
  (`travel_ticks_per_100_units`), с округлением до ближайшего целого, не меньше 1.

Id в готовой карте: узлы половины с копией по порядку файла получают `0..k−1`, узлы, зеркальные
сами себе, следом по порядку файла, зеркало узла `i` — `N−1−i`. Дороги половины с копией получают
`0..e−1`, их копии `e..2e−1`, затем дороги между узлами, зеркальными самим себе; затем
`cross_edges` по порядку, каждая со своей копией следом.

## Превью

`uv run gow-maps preview maps/*.json` (MAP-04, #16) рисует рядом с каждой картой
`maps/<name>.preview.png` (matplotlib): дороги (тёмная линия: уровень 1 на старте, светлая
подложка: `max_level`), точка границы (кружок на дороге), узлы (цвет: стартовый владелец, форма:
рельеф, звезда: столица), подписи `id`, вид узла (S, M, L: малый, средний, большой город; P:
провинция), название, `vp` и стартовый гарнизон «заряжено/юнитов». Превью — только для людей; пул карт
и их характер описаны в [`maps/README.md`](../../maps/README.md).

## Пул карт на сервере

Сервер (`gow_server.maps`, SRV-01) при старте загружает все `maps/*.json` (без подкаталогов:
в `maps/src/` лежат половины) через `load_map`. Имя файла обязано совпадать с `meta.name`:
`maps/<id>.json`. Битая карта или несовпадение имени останавливают запуск сервера.

Фон карты (MAP-05) лежит рядом: `maps/<id>.bg.webp`. Он необязателен; превью PNG из MAP-04 (другие
файлы) сервер не раздаёт. Как фон устроен и как его перепечь: раздел «Фон карты» ниже.

| Запрос | Ответ |
|---|---|
| `GET /api/maps` | `[{id, version, width, height, background_url}]`, по `id`; `background_url` равен `null`, если фона нет |
| `GET /api/maps/{id}` | файл карты как есть (география публична: mechanics.md, раздел 10) |
| `GET /api/maps/{id}/background.webp` | фон (`image/webp`) или 404 |

## Фон карты

`uv run gow-maps bake maps/*.json` (MAP-05, #70) рисует рядом с каждой картой `maps/<id>.bg.webp`.
Фон только для красоты: правила игры его не читают. Запекатель на `numpy` и `Pillow` (решение владельца
2026-10-21, `ui-style.md`, 26.3; до #344 был PNG на стандартной библиотеке).

- **Размер и привязка.** Картинка ровно `width × height` пикселей: один пиксель на единицу мира, левый
  верхний пиксель в точке `(0, 0)`, ось `y` вниз. Клиент кладёт спрайт фона в `(0, 0)` с размером
  `meta.width × meta.height` в мировых координатах, в тех же, в которых рисует узлы и дороги.
- **Сетка.** Поле считается по сетке с шагом 4 единицы мира (как в прототипе на Pygame), поэтому `width` и
  `height` карты с фоном кратны 4; иначе `bake` завершается ошибкой. Сетка задаёт только раскладку биомов; картинка рисуется в полном
  разрешении и квадратов 4 × 4 не показывает.
- **Воды нет** (DEC-27, п. 3, #269): в фоне нет моря, мелководья и пляжа, каждая клетка суша.
  Раньше фон считался metaballs из генератора карт прототипа на Pygame (тег `v0-pygame-prototype`):
  плотность городов и дорог с порогом и волновым шумом, ниже порога море, узкая полоса над порогом
  берег. Владелец находит воду запутывающей. Цвет джунглей из прототипа (бирюзовый) заменён
  зелёным, чтобы он не читался как вода.
- **Биом области.** Область узла: клетки, ближе всего к нему (Voronoi с искривлёнными шумом
  границами). Биом следует рельефу узла: равнина: степь или саванна, лес: лес или джунгли, горы:
  скалы или снег. Вариант внутри рельефа и оттенок выбирает шум влажности и деталей из прототипа.
- **Текстура T2 «Прореживание»** (`ui-style.md`, 26.3; макет `mockups/map-style-2.html`, прототип
  `mockups/src/map_textures.py`). Плоская земля биома двух тонов пятнами; между биомами узкая полоса
  цвета (около 14 px), которая «гуляет» по шуму; детали (кроны деревьев, пучки травы, камни, штрихи снега)
  редеют и уменьшаются к краю биома; чуть зерна сверху. Без теней, света и рельефа. Раскладка биомов
  та же, что у прежнего запекателя (поле `bake_cells` не менялось).
- **Детерминизм.** Шум задаётся зерном из `blake2b(name:version)` карты (или `--seed`): смещения
  поля биомов из `random.Random`, поля текстур из `numpy.random.default_rng`. Два запуска в одном окружении дают
  одинаковые пиксели. Фон не обязан быть симметричным (DEC-27, п. 1): каждая клетка ищет свой ближайший узел.
- **Формат и вес.** WebP с потерями (`quality=85`, `method=6`). Файл не больше 0,5 МБ (сейчас
  230–300 КБ; `bake` отказывает, если больше), запекание одной карты до 10 с. Байты файла зависят от
  libwebp колеса Pillow, поэтому тест `tools/maps/tests/test_bake.py` сверяет закоммиченные фоны со свежим запеканием
  по средним цветам блоков 16 × 16 с допуском, а не побайтно: правка карты без `bake` ломает CI.
- **Штампы клиента.** Карта с запечёнными деталями не получает штампов `TerrainView` (около 1300 спрайтов):
  они остаются только у карт без фона и у карты, фон которой не загрузился.
