# Формат карты

Карта MVP: JSON-файл в `maps/`. Загрузчик: `gow_sim.maps.load_map(path) -> MapDef` (MAP-01, #13).
Проверки дизайна карты (связность, планарность, симметрия атрибутов, нейтральное пространство)
выполняет офлайн-валидатор `uv run gow-maps validate maps/*.json` (MAP-02, #14).

Правила игры, которые опираются на поля карты, описаны в [`mechanics.md`](mechanics.md): рельеф
(раздел 4), дороги (раздел 8), города и ёмкость (раздел 9), VP (раздел 11).

## Общие правила

- **Все числа целые.** `1.0`, `"1"` и `true` вместо числа: ошибка загрузки.
- **Id узлов и рёбер равны их позиции в списке:** `nodes[i].id == i`, `edges[i].id == i`.
  Внутри симуляции узлы и рёбра хранятся по этим id.
- **Неизвестный или отсутствующий ключ:** ошибка (опечатка не проходит молча).
- Игроки MVP: `0` и `1`. «Нет владельца»: `null`.
- Координаты: целые «единицы мира» в прямоугольнике `[0, width] × [0, height]`, ось `y` вниз
  (как на экране).

Ошибка загрузки называет файл и поле: `maps/x.json: nodes[3].vp: expected an integer, got 1.5`.

## Структура

```json
{
  "meta":   {"name": "line3", "version": 1, "symmetry": "rot180", "width": 400, "height": 200},
  "nodes":  [{"id": 0, "x": 100, "y": 100, "terrain": "mountains", "vp": 1, "base_capacity": 4,
              "capital_of": 0, "start_owner": 0, "start_units": 3, "start_charged": 3, "start_stock": 4}],
  "edges":  [{"id": 0, "a": 0, "b": 1, "base_width": 1, "max_width": 3, "travel_ticks": 30}],
  "mirror": {"nodes": {"0": 2, "1": 1, "2": 0}, "edges": {"0": 1, "1": 0}}
}
```

### `meta`

| Поле | Тип | Значение |
|---|---|---|
| `name` | строка `[A-Za-z0-9_-]+` | id карты (`map_id` в реплее и протоколе) |
| `version` | целое ≥ 1 | ревизия карты; повышается при любой правке |
| `symmetry` | `"rot180"` | тип симметрии; в MVP только поворот на 180° |
| `width`, `height` | целые ≥ 1 | размер мира; центр поворота: `(width / 2, height / 2)` |

### `nodes[]`

В MVP **каждый узел — город со складом** (mechanics.md, раздел 9).

| Поле | Тип | Значение |
|---|---|---|
| `id` | целое | равно индексу в списке |
| `x`, `y` | целые | позиция, `0 ≤ x ≤ width`, `0 ≤ y ≤ height` |
| `terrain` | `plains` \| `forest` \| `mountains` | рельеф: равнина, лес, горы (mechanics.md, раздел 4) |
| `vp` | целое ≥ 0 | VP за удержание города; у столицы множитель из рулсета (DEC-03) |
| `base_capacity` | целое ≥ 0 | база ёмкости до вклада дорог (mechanics.md, раздел 9) |
| `capital_of` | `null` \| `0` \| `1` | чья это столица |
| `start_owner` | `null` \| `0` \| `1` | владелец на старте |
| `start_units` | целое ≥ 0 | стартовый гарнизон: число юнитов |
| `start_charged` | целое, `0..start_units` | из них заряжены |
| `start_stock` | целое ≥ 0 | стартовый запас склада в зарядах |

Загрузчик дополнительно требует:

- у каждого игрока ровно одна столица, и на старте она принадлежит ему;
- **нейтральный узел** (`start_owner: null`) пуст: `start_units`, `start_charged` и `start_stock`
  равны 0. Нейтральных гарнизонов в MVP нет.

### `edges[]`

Дорога неориентирована. Между двумя узлами не больше одной дороги, петли запрещены.

| Поле | Тип | Значение |
|---|---|---|
| `id` | целое | равно индексу в списке |
| `a`, `b` | id узлов | концы дороги, `a ≠ b` |
| `base_width` | целое, `1..max_width` | ширина на старте |
| `max_width` | целое, `1..5` | предел улучшения (SIM-11); 5: последняя ширина таблицы ёмкости (mechanics.md, раздел 9) |
| `travel_ticks` | целое ≥ 1 | базовое время прохода в тиках; модификатор рельефа узла входа берётся из рулсета (`terrain.entry_speed_pct`) |

`travel_ticks` согласован с геометрической длиной дороги; допуск проверяет валидатор (раздел «Валидатор»).

### `mirror`

Таблица симметрии: `nodes` и `edges` отображают id в id зеркального объекта при повороте на 180°.
Ключи: id в виде строк (так устроен JSON), значения: целые id.

- Таблица полная (у каждого узла и ребра есть зеркало) и является инволюцией: `m(m(x)) == x`.
- Узел в точном центре карты зеркален сам себе; его `start_owner` и `capital_of` равны `null`.
- Зеркало ребра `(a, b)` соединяет `m(a)` и `m(b)`.
- У зеркального узла те же атрибуты, а `capital_of` и `start_owner` переходят к другому игроку;
  координаты: `(width − x, height − y)`.

Загрузчик проверяет только полноту и инволютивность. Совпадение атрибутов, концов рёбер и координат
проверяет валидатор (MAP-02).

**Зачем таблица симуляции.** Тай-брейки по узлам идут через `MapDef.node_key(player, node)`:
для игрока 0 это id узла, для игрока 1 — id зеркального узла (`AGENTS.md`, раздел 4.1, правило 6).
Поэтому решение в зеркальной позиции тоже зеркально, и тест зеркальности (SIM-05) не ловит
преимущества стороны, внесённого порядком id.

## Тип карты в клиенте

Клиент читает файл карты по типу `MapFile` из `apps/client/src/protocol.gen.ts`. Тип сгенерирован
из модели `gow_protocol.mapfile.MapFile` (PRO-02, #45): она описывает только форму и типы значений,
а ссылки, диапазоны между полями и зеркало проверяет загрузчик. Тест
`packages/protocol/tests/test_mapfile.py` проверяет, что модель и загрузчик согласны на всех картах
`maps/` и `packages/sim/tests/maps/`. Поменял формат: поправь загрузчик, модель и перегенерируй типы
(`AGENTS.md`, раздел 3).

## `MapDef` в коде

`gow_sim.maps` (только стандартная библиотека):

- `MapDef(meta, nodes, edges, mirror_nodes, mirror_edges, incident)`: frozen dataclass; `nodes` и
  `edges` — кортежи `NodeDef` и `EdgeDef`, индекс равен id; `incident[n]` — id рёбер узла `n`
  по возрастанию.
- `MapDef.capital(player)`, `MapDef.node_key(player, node)`, `EdgeDef.other(node)`.
- `load_map(path)` и `parse_map(data)`; ошибки: `MapFormatError` (подкласс `ValueError`).
- `map_to_data(map)`: обратное к `parse_map` (данные в формате файла); так карта входит в каноническое состояние и `state_hash()` (SIM-02).

## Валидатор

`uv run gow-maps validate <файлы>` (MAP-02, #14) загружает каждую карту и проверяет дизайн.
Вывод: `OK <файл>` или `FAIL <файл>` со списком `[проверка] сообщение`; код выхода 1, если
хоть одна карта не прошла. Шаблоны вроде `maps/*.json` раскрываются и самим CLI (bash передаёт
несовпавший шаблон как есть). Пороги: `tools/maps/src/gow_maps/validate.toml`, другой файл:
`--config <путь>`.

| Проверка | Что требует |
|---|---|
| `format` | карта загружается `gow_sim.maps` (типы, ссылки, диапазоны, пустые нейтральные узлы) |
| `connectivity` | граф связен |
| `planarity` | дороги не пересекаются и не накладываются, дорога не проходит через чужой город, у городов разные координаты |
| `symmetry` | таблица `mirror` задаёт поворот на 180°: координаты `(width − x, height − y)`, одинаковые атрибуты узлов и рёбер (включая стартовые поля), владелец и столица переходят к другому игроку, концы зеркального ребра зеркальны |
| `degree` | у узла не больше `max_degree` (5) дорог |
| `disjoint_paths` | от каждой столицы к каждому узлу с `vp ≥ 2` не меньше 2 путей без общих дорог |
| `neutral_space` | не меньше 20% узлов без стартового владельца, у которых расстояния до двух столиц (в дорогах) отличаются не больше чем на 1 |
| `travel_ticks` | `travel_ticks` ≈ длина × 30 / 100 (100 единиц мира = 3 секунды), допуск 25%, не меньше 1 тика |

Проверки путей и расстояний выполняются только на связном графе. «Плохие» фикстуры для каждой
проверки: `tools/maps/tests/fixtures/`.

## Половина карты и отзеркаливание

Карты MVP рисуются наполовину, вторую половину строит скрипт (MAP-03, #15):

```bash
uv run gow-maps mirror maps/src/<name>.half.json -o maps/<name>.json
```

Скрипт поворачивает половину на 180°, сшивает дороги через центральную полосу, назначает id и
таблицу `mirror`, пишет карту и сразу прогоняет её через валидатор (код выхода 1, если карта не
прошла; файл при этом остаётся для разбора).

Формат половины (`maps/src/<name>.half.json`):

```json
{
  "meta":  {"name": "diamond", "version": 1, "width": 400, "height": 400},
  "nodes": [{"id": "capital", "x": 100, "y": 200, "terrain": "mountains", "vp": 1, "base_capacity": 4,
             "capital_of": 0, "start_owner": 0, "start_units": 3, "start_charged": 3, "start_stock": 4},
            {"id": "north", "x": 200, "y": 100, "terrain": "forest", "vp": 2, "...": "..."}],
  "edges":       [{"a": "capital", "b": "north", "base_width": 1, "max_width": 3}],
  "cross_edges": [{"a": "capital", "b": "north", "base_width": 1, "max_width": 3}]
}
```

- `meta` без `symmetry`: половина всегда собирается поворотом на 180°.
- `nodes[].id`: строковая метка, уникальная в файле; остальные поля как у карты. Узел в точном
  центре `(width / 2, height / 2)` зеркален сам себе и не копируется (такой узел не больше одного).
  У копии остальных узлов координаты `(width − x, height − y)`, а `capital_of` и `start_owner`
  переходят к другому игроку.
- `edges[]`: дорога между двумя узлами половины; копия соединяет их зеркала.
- `cross_edges[]`: дорога через центральную полосу от узла `a` к **зеркалу** узла `b`; её копия
  идёт от `b` к зеркалу `a`. При `a == b` получается одна дорога, зеркальная сама себе. Центральный
  узел соединяется обычными `edges`.
- `travel_ticks` у дорог можно не указывать: скрипт посчитает его по длине с тем же масштабом, что
  у валидатора (`travel_ticks_per_100_units`), с округлением до ближайшего целого, не меньше 1.

Id в готовой карте: узлы половины по порядку файла получают `0..k−1`, центральный узел `k`,
зеркало узла `i` — `N−1−i`. Дороги половины получают `0..e−1`, их копии `e..2e−1`; затем
`cross_edges` по порядку, каждая со своей копией следом.

## Превью

`uv run gow-maps preview maps/*.json` (MAP-04, #16) рисует рядом с каждой картой
`maps/<name>.preview.png` (matplotlib): дороги (тёмная линия — ширина на старте, светлая
подложка — `max_width`), города (цвет — стартовый владелец, форма — рельеф, звезда — столица),
подписи `id`, `vp` и стартовый гарнизон «заряжено/юнитов». Превью — только для людей; пул карт
и их характер описаны в [`maps/README.md`](../../maps/README.md).

## Пул карт на сервере

Сервер (`gow_server.maps`, SRV-01) при старте загружает все `maps/*.json` (без подкаталогов:
в `maps/src/` лежат половины) через `load_map`. Имя файла обязано совпадать с `meta.name`:
`maps/<id>.json`. Битая карта или несовпадение имени останавливают запуск сервера.

Фон карты (MAP-05) лежит рядом: `maps/<id>.bg.png`. Он необязателен; превью PNG из MAP-04 (другие
файлы) сервер не раздаёт. Как фон устроен и как его перепечь: раздел «Фон карты» ниже.

| Запрос | Ответ |
|---|---|
| `GET /api/maps` | `[{id, version, width, height, background_url}]`, по `id`; `background_url` равен `null`, если фона нет |
| `GET /api/maps/{id}` | файл карты как есть (география публична: mechanics.md, раздел 10) |
| `GET /api/maps/{id}/background.png` | фон или 404 |

## Фон карты

`uv run gow-maps bake maps/*.json` (MAP-05, #70) рисует рядом с каждой картой `maps/<id>.bg.png`.
Фон только для красоты: правила игры его не читают.

- **Размер и привязка.** PNG ровно `width × height` пикселей: один пиксель на единицу мира, левый
  верхний пиксель в точке `(0, 0)`, ось `y` вниз. Клиент кладёт спрайт фона в `(0, 0)` с размером
  `meta.width × meta.height` в мировых координатах, в тех же, в которых рисует узлы и дороги.
- **Сетка.** Поле считается по сетке с шагом 4 единицы мира (как в legacy), поэтому `width` и
  `height` карты с фоном кратны 4; иначе `bake` завершается ошибкой. Каждая клетка сетки на PNG
  выглядит квадратом 4 × 4 пикселя.
- **Суша и море** (metaballs из `legacy/rts_core/game_logic/World/MapGenerator.py`): каждый город и
  каждая дорога добавляют «плотность» в радиусе 95 единиц; где плотность с волновым шумом ниже
  порога, там море, узкая полоса над порогом: берег. Города и дороги всегда на суше.
- **Биом области.** Область узла: клетки, ближе всего к нему (Voronoi с искривлёнными шумом
  границами). Биом следует рельефу узла: равнина: степь или саванна, лес: лес или джунгли, горы:
  скалы или снег. Вариант внутри рельефа и оттенок выбирает шум влажности и деталей из legacy.
- **Детерминизм.** Шум задаётся зерном из `blake2b(name:version)` карты (или `--seed`); фон
  симметричен поворотом на 180°, как сама карта. Тест `tools/maps/tests/test_bake.py` сверяет
  пиксели закоммиченных фонов со свежим запеканием: правка карты без `bake` ломает CI.
- **Вес.** Каждый PNG не больше 1,5 МБ (сейчас 55–95 КБ).

## Тестовые карты

Крошечные карты для сценарных тестов симуляции лежат в `packages/sim/tests/maps/`:

| Файл | Что это |
|---|---|
| `line3.json` | линия из 3 узлов: столица — нейтральный город — столица |
| `diamond.json` | ромб 1v1: две столицы и два нейтральных города по флангам (`vp` 2) |
| `pass.json` | «перевал»: у каждого игрока столица и передовой город, между ними единственный проход через горный узел хребта |

Dev-экран клиента (CLI-03, #59) собирает в бандл `maps/*.json` и эти тестовые карты
(`apps/client/src/map/bundledMaps.ts`), поэтому их правка запускает и проверку `web` в CI.
