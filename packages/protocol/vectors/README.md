# Тест-векторы

Общие данные для тестов симуляции (Python) и клиента (TypeScript). Ожидаемые значения берутся
только из `docs/design/mechanics.md` и таблиц DEC, а не из вывода кода (`AGENTS.md`, раздел 0).
Изменил правило в mechanics.md: сначала поправь вектор, потом код.

Структуру файлов проверяет `packages/protocol/tests/test_vectors.py`.

## `combat.json`: разрешение боя (DEC-07, #11)

Шестнадцать разобранных примеров из mechanics.md, раздел 4, «Разрешение боя (DEC-07, #11)».
По ним тестируются бой в симуляции (SIM-09, #25) и оценка боя в клиенте (CLI-08, #64).

Верхний уровень:

| Поле | Значение |
|---|---|
| `schema_version` | версия схемы файла, сейчас `1` |
| `source` | откуда взяты правила и примеры |
| `params` | числа правил, с которыми посчитаны примеры: `terrain_defense_mod` (`mountains` / `forest` / `plains`), `planned_bonus`, `defense_bonus`. Совпадают с `rulesets/mvp-0.toml` |
| `vectors` | список примеров, `id` от 1 до 16 совпадает с номером строки таблицы |

Пример (`vectors[i]`). Стороны всегда называются `a` и `b`: в бою за узел `a` атакует, `b` защищает.

| Поле | Значение |
|---|---|
| `id` | номер строки таблицы DEC-07 |
| `source_row` | ячейки строки таблицы как есть: `attack`, `defense`, `result` |
| `location` | `node_attack` (атака на занятый вражеский узел), `edge_meeting` (встреча на ребре, правило 6), `neutral_arrival` (одновременное прибытие в нейтральный узел, правило 5), `empty_enemy_node` (вражеский узел без юнитов) |
| `terrain` | рельеф узла: `mountains`, `forest`, `plains`; `null`, если рельеф по правилам не участвует (ребро, нейтральный узел) |
| `node_owner_before` | владелец узла до боя: `a`, `b`, `neutral`; `null` для ребра |
| `sides.<a\|b>.role` | `attacker`, `defender` или `symmetric` (бой без защитника: ребро и нейтральный узел) |
| `sides.<a\|b>.bonus` | `null` или `{source, amount}`, где `source` — `planned_order` (запланированный приказ) или `defense_mode` (режим «Защита», уже активный). Это бонус, с которым сторона приходит в бой; действует ли он, решают правила (правило 1) |
| `sides.<a\|b>.groups` | группы стороны: `id` (уникален внутри вектора), `units`, `charged`, `mode` (`attack`, `defense`, `build`) |
| `expected.pool` | пул Q каждой стороны после правила 1 (заряды стреляющих юнитов + действующий бонус + действующий рельеф); `null`, если боя нет (`empty_enemy_node`) |
| `expected.losses` | сколько юнитов потеряла каждая сторона (то есть убил противник) |
| `expected.groups` | те же группы после боя: `id`, `units`, `charged`; уничтоженная группа остаётся в списке с `units = 0` |
| `expected.bounce` | отскакивает ли сторона (правила 4–6) |
| `expected.node_owner_after` | владелец узла после боя: `a`, `b`, `neutral`; `null` для ребра |
| `expected.continues_on_edge` | для `edge_meeting`: продолжает ли сторона путь по ребру; иначе `null` |
| `note` | вывод результата по правилам 1–9 шаг за шагом |

Инварианты, которые проверяет тест: `id` уникальны и идут 1…16; у каждой группы `0 ≤ charged ≤ units`;
`expected.groups` содержит ровно группы из входа; потери стороны равны разнице суммы `units` до и после
боя; заряды не появляются из ниоткуда.
